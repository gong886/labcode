### 2.1 练习一：加载应用程序并执行（需要编码）
首先了解打开文件的处理流程，然后参考本实验后续的文件读写操作的过程分析，填写在 kern/fs/sfs/sfs_inode.c中 的sfs_io_nolock()函数，实现读文件中数据的代码。

#### 打开文件的处理流程

1. 应用程序调用 `open(path, open_flags)` 函数（`user/libs/file.c`）。`open` 函数调用 `sys_open`（`user/libs/syscall.c`）。`sys_open` 执行 `syscall(SYS_open, path, open_flags)`，触发系统调用中断（`ecall`），进入内核态。
2. 内核的中断处理程序将控制权转交给 `syscall` 函数（ `kern/syscall/syscall.c`）。`syscall` 根据系统调用号分发给 `sys_open` 函数（位于 `kern/syscall/syscall.c`）。
`sys_open` 调用 `sysfile_open`（位于 `kern/fs/sysfile.c`）。
3. `sysfile_open` 将文件路径字符串从用户空间拷贝到内核空间，然后调用 `file_open`（位于 `kern/fs/file.c`）。
`file_open` 主要完成：检查 `open_flags`。调用 `fd_array_alloc` 在当前进程的文件描述符表中分配一个空闲的 `file` 结构体和对应的文件描述符 `fd`。调用 `vfs_open`（位于 `kern/fs/vfs/vfsfile.c`）来获取文件对应的 `inode`。
4. `vfs_open` 调用 `vfs_lookup` 查找路径对应的 `inode`。如果文件不存在且设置了 `O_CREAT`，则会调用 `vop_create` 创建新文件。`vfs_lookup` 会逐层解析路径，调用具体文件系统（如 SFS）的 `vop_lookup`（即 `sfs_lookup`）来查找目录项和加载 inode。找到 `inode` 后，`vfs_open` 调用 `vop_open`（即 `sfs_openfile` 或 `sfs_opendir`）进行具体文件系统的打开操作。如果设置了 `O_TRUNC`，则调用 `vop_truncate` 将文件截断为 0。
5. `vfs_open` 成功返回 `inode` 后，`file_open` 将该 `inode`、访问权限、当前读写位置（pos）等信息填入之前分配的 `file` 结构体中。调用 `fd_array_open` 将该文件结构体的状态标记为 `FD_OPENED`。最后，`sysfile_open` 返回文件描述符 `fd` 给用户态程序。



#### 设计思路

`sfs_io_nolock` 函数主要负责将内存缓冲区 `buf` 中的数据写入文件，或者将文件中的数据读取到 `buf` 中。由于文件在磁盘上是以块为单位存储的，而读写请求的偏移量和长度可能不是块对齐的，因此需要分三种情况处理：

1.  起始非对齐部分：如果读写操作的起始偏移量 `offset` 不是块对齐的，则需要先处理该块中从 `offset` 开始到块结束的部分。这部分通常使用 `sfs_buf_op`进行非对齐读写。
2.  中间对齐块部分：处理完起始非对齐部分后，如果剩余的读写长度超过一个块的大小，则可以按块进行批量读写。这部分是读写操作的主体，使用 `sfs_block_op`直接对整个块进行操作，效率较高。
3.  结尾非对齐部分：处理完中间的对齐块后，如果还有剩余数据，则说明结束位置不是块对齐的。这部分同样使用 `sfs_buf_op` 处理该块从起始位置到结束位置的数据。

在上述每一步中，都需要先调用 `sfs_bmap_load_nolock` 函数，根据文件的逻辑块号获取其在磁盘上的物理块号。如果是在写操作中且该块尚未分配，`sfs_bmap_load_nolock` 还会负责分配新的磁盘块。

#### 代码实现

```c
    //对齐部分
    if ((blkoff = offset % SFS_BLKSIZE) != 0) {
        size = (nblks != 0) ? (SFS_BLKSIZE - blkoff) : (endpos - offset);
        if ((ret = sfs_bmap_load_nolock(sfs, sin, blkno, &ino)) != 0) {
            return ret;
        }
        if ((ret = sfs_buf_op(sfs, buf, size, ino, blkoff)) != 0) {
            return ret;
        }
        alen += size;
        buf += size;
        if (nblks == 0) {
            goto out;
        }
        blkno ++;
        nblks --;
    }

    // 中间对齐块
    if (nblks > 0) {
        int i;
        for (i = 0; i < nblks; i ++) {
            if ((ret = sfs_bmap_load_nolock(sfs, sin, blkno, &ino)) != 0) {
                return ret;
            }
            if ((ret = sfs_block_op(sfs, buf, ino, 1)) != 0) {
                return ret;
            }
            alen += SFS_BLKSIZE;
            buf += SFS_BLKSIZE;
            blkno ++;
        }
    }

    // 结束非对齐部分
    if ((size = endpos % SFS_BLKSIZE) != 0) {
        if ((ret = sfs_bmap_load_nolock(sfs, sin, blkno, &ino)) != 0) {
            return ret;
        }
        if ((ret = sfs_buf_op(sfs, buf, size, ino, 0)) != 0) {
            return ret;
        }
        alen += size;
    }
```

4. load_icode():
```
static int
load_icode(int fd, int argc, char **kargv)
{
// (1) 检查当前进程是否已有内存管理结构 mm
    if (current->mm != NULL) {
        panic("load_icode: current->mm must be NULL.\n");
    }

    int ret = -E_NO_MEM;
    struct mm_struct *mm;
    // (1) 为当前进程创建一个新的 mm
    if ((mm = mm_create()) == NULL) {
        goto bad_mm;
    }

    // (2) 创建一个新的页目录表 (PDT)
    if (setup_pgdir(mm) != 0) {
        goto bad_pgdir_cleanup_mm;
    }

    // (3) 解析 ELF 文件
    struct elfhdr __elf, *elf = &__elf;
    if ((ret = load_icode_read(fd, elf, sizeof(struct elfhdr), 0)) != 0) {
        goto bad_elf_cleanup_pgdir;
    }
    if (elf->e_magic != ELF_MAGIC) {
        ret = -E_INVAL_ELF;
        goto bad_elf_cleanup_pgdir;
    }

    struct proghdr __ph, *ph = &__ph;
    uint32_t vm_flags, perm;
    for (int i = 0; i < elf->e_phnum; i++) {
        off_t phoff = elf->e_phoff + sizeof(struct proghdr) * i;
        if ((ret = load_icode_read(fd, ph, sizeof(struct proghdr), phoff)) != 0) {
            goto bad_cleanup_mmap;
        }
        if (ph->p_type != ELF_PT_LOAD) {
            continue;
        }
        if (ph->p_filesz > ph->p_memsz) {
            ret = -E_INVAL_ELF;
            goto bad_cleanup_mmap;
        }
        if (ph->p_memsz == 0) {
            continue;
        }

        // --- 修正重点：权限位映射 ---
        vm_flags = 0, perm = PTE_U | PTE_V;
        if (ph->p_flags & ELF_PF_X) vm_flags |= VM_EXEC;
        if (ph->p_flags & ELF_PF_W) vm_flags |= VM_WRITE;
        if (ph->p_flags & ELF_PF_R) vm_flags |= VM_READ;
        
        // 关键：必须根据 ELF 段标志设置对应的 PTE 权限
        if (vm_flags & VM_READ)  perm |= PTE_R;
        if (vm_flags & VM_WRITE) perm |= (PTE_R | PTE_W);
        if (vm_flags & VM_EXEC)  perm |= PTE_X; // 修复 Instruction page fault 的关键

        // (3.3) 建立 VMA 映射
        if ((ret = mm_map(mm, ph->p_va, ph->p_memsz, vm_flags, NULL)) != 0) {
            goto bad_cleanup_mmap;
        }

        // (3.4) 分配物理内存并读取 TEXT/DATA 段
        off_t offset = ph->p_offset;
        size_t off, size;
        uintptr_t start = ph->p_va, end = ph->p_va + ph->p_filesz;
        uintptr_t la = ROUNDDOWN(start, PGSIZE);

        struct Page *page;
        while (la < end) {
            if ((page = pgdir_alloc_page(mm->pgdir, la, perm)) == NULL) {
                ret = -E_NO_MEM;
                goto bad_cleanup_mmap;
            }
            off = (la < start) ? start - la : 0;
            size = (ROUNDUP(la + 1, PGSIZE) > end) ? end - la - off : PGSIZE - off;
            if ((ret = load_icode_read(fd, page2kva(page) + off, size, offset)) != 0) {
                goto bad_cleanup_mmap;
            }
            la += PGSIZE;
            offset += size;
        }

        // (3.5) 处理 BSS 段
        end = ph->p_va + ph->p_memsz;
        if (la < end) {
            while (la < end) {
                if ((page = pgdir_alloc_page(mm->pgdir, la, perm)) == NULL) {
                    ret = -E_NO_MEM;
                    goto bad_cleanup_mmap;
                }
                off = (la < start + ph->p_filesz) ? start + ph->p_filesz - la : 0;
                size = (ROUNDUP(la + 1, PGSIZE) > end) ? end - la - off : PGSIZE - off;
                memset(page2kva(page) + off, 0, size);
                la += PGSIZE;
            }
        }
    }
    sysfile_close(fd);

    // (4) 设置用户栈
    vm_flags = VM_READ | VM_WRITE | VM_STACK;
    if ((ret = mm_map(mm, USTACKTOP - USTACKSIZE, USTACKSIZE, vm_flags, NULL)) != 0) {
        goto bad_cleanup_mmap;
    }
    // 分配用户栈顶部的物理页，权限使用 PTE_USER
    assert(pgdir_alloc_page(mm->pgdir, USTACKTOP - PGSIZE, PTE_USER) != NULL);
    assert(pgdir_alloc_page(mm->pgdir, USTACKTOP - 2 * PGSIZE, PTE_USER) != NULL);
    assert(pgdir_alloc_page(mm->pgdir, USTACKTOP - 3 * PGSIZE, PTE_USER) != NULL);
    assert(pgdir_alloc_page(mm->pgdir, USTACKTOP - 4 * PGSIZE, PTE_USER) != NULL);

    // (5) 设置当前进程的 mm, cr3 并刷新 TLB
    mm_count_inc(mm);
    current->mm = mm;
    current->pgdir = PADDR(mm->pgdir);
    lsatp(current->pgdir);
    flush_tlb();

    // (6) 处理用户栈参数 (argc, argv)
    uint32_t argv_size = 0;
    for (int i = 0; i < argc; i++) {
        argv_size += strnlen(kargv[i], EXEC_MAX_ARG_LEN) + 1;
    }

    uintptr_t stacktop = USTACKTOP - (ROUNDUP(argv_size, sizeof(long)) + ROUNDUP(argc * sizeof(char *), sizeof(long)));
    char **uargv = (char **)(stacktop);
    char *p = (char *)(stacktop + argc * sizeof(char *));

    for (int i = 0; i < argc; i++) {
        uargv[i] = p;
        strcpy(p, kargv[i]);
        p += strnlen(kargv[i], EXEC_MAX_ARG_LEN) + 1;
    }

    // (7) 初始化用户态中断帧
    struct trapframe *tf = current->tf;
    uintptr_t sstatus = tf->status; // 备份当前状态
    memset(tf, 0, sizeof(struct trapframe));
    tf->epc = elf->e_entry;       // 程序入口
    tf->gpr.sp = stacktop;        // 用户栈顶
    // 确保 SPP=0 (用户态) 且开启中断 SPIE=1
    tf->status = (sstatus & ~SSTATUS_SPP) | SSTATUS_SPIE;
    tf->gpr.a0 = argc;
    tf->gpr.a1 = stacktop;

    ret = 0;
out:
    return ret;

bad_cleanup_mmap:
    exit_mmap(mm);
bad_elf_cleanup_pgdir:
    put_pgdir(mm);
bad_pgdir_cleanup_mm:
    mm_destroy(mm);
bad_mm:
    goto out;
}
```
1. 创建新的内存管理结构 mm 

内核首先为当前进程创建一个全新的 mm_struct。 

作用：mm 是进程虚拟内存的“大管家”，负责管理所有的虚存区域（VMA）。因为我们要运行一个新的程序，必须丢弃旧的内存布局。 

2. 创建新的页目录表 PDT 

为该进程分配物理页作为页表，并将 mm->pgdir 指向该页表的内核虚拟地址。 

作用：建立进程私有的地址空间映射。此时，页表中只包含了内核空间的映射（拷贝自内核基准页表），用户空间还是空的。 

3. 拷贝程序的 TEXT/DATA/BSS 到进程空间 

这是最复杂的一步，分为 5 个小环节： 

3.1 & 3.2 解析 ELF 头部和程序头表： 内核通过 load_icode_read 从磁盘读取 ELF 文件头。程序头表（Proghdr）描述了二进制文件中哪些部分需要加载到内存中。 

3.3 建立 VMA 映射： 对于每个 ELF_PT_LOAD 类型的段，调用 mm_map 在 mm 中注册一段虚拟地址空间。比如代码段映射到 0x800000 附近的区域。 

3.4 分配物理内存并读取文件内容： 这是 Lab 8 的关键。内核循环调用 pgdir_alloc_page 分配物理页，并建立与虚拟地址的映射。然后，直接**从磁盘文件读取代码（TEXT）和初始化数据（DATA）**到这些物理页中。 

3.5 处理 BSS 段： BSS 存放未初始化的全局变量。文件里不存这些数据，但内核需要分配内存页，并调用 memset 将其清零。 

4. 设置用户栈并处理初始参数  

内核调用 mm_map 在用户空间的顶部（通常是 USTACKTOP 以下）建立用户栈的 VMA，并分配物理页面。 

作用：为程序运行提供临时的存储空间。 

5. 设置当前进程的 MM 和页表寄存器  

更新 MM：将新创建的 mm 挂载到 current->mm。 

切换页表：通过 lsatp（RISC-V）或 lcr3（x86）指令，将新页表的物理地址加载到 CPU 的页表基址寄存器中。 

刷新 TLB：执行 flush_tlb 确保之前的地址转换缓存失效。 

6. 在用户栈中设置 argc 和 argv  

这是一个技巧性很强的步骤。内核需要把用户输入的命令行参数（如 ls -l）从内核缓冲区拷贝到用户栈的特定位置。 

作用：按照 C 语言的标准，将参数压栈，并设置好 argv 指针数组，使 main(int argc, char **argv) 函数能正确接收参数。 

7. 设置用户态中断帧 trapframe 

在返回用户态前，必须伪造一个“现场”： 

tf->epc：指向 ELF 文件的入口地址（Entry Point）。 

tf->sp：指向刚才设置好的用户栈顶。 

权限位：确保状态寄存器设置为“用户模式”且“开启中断”。 

参数寄存器：根据调用约定（如 RISC-V 的 a0, a1），将 argc 和 stacktop 存入寄存器。 

8. 错误处理与环境清理 

如果在上述任何一步（如磁盘读取失败、内存不足）出错，内核必须执行完整的清理工作： 

exit_mmap(mm)：释放已经映射的所有虚存区域。 

put_pgdir(mm)：释放页表占有的物理内存。 

mm_destroy(mm)：销毁 MM 结构体。 

作用：防止内核内存泄漏，确保系统不会因为一次程序加载失败而崩溃。
